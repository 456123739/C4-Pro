## C4-Pro v1.7.3 更新日志（2026-10）

> 安装队（匪）永远不能拆包，拆除队（警）永远不能下包；顺带加了启动日志和 `/c4roles` 排错指令。

### 🔊 音效改回原版（撤销 1.7.0 的自造滴滴声）

- 删除 `qis4c4:c4beep`（音频文件、sounds.json 条目、语言键、注册项一并删除）；
- 安装成功：`qis4c4:c4countdown`（40 秒整段，3.0 音量）+ `qis4c4:c4plant`（“Bomb has been planted”语音，1.0）；
- 滴答：原版 `minecraft:block.note_block.hat`（1.5），节奏逐字恢复原版公式
  `max(8, (int)(40 * (1 - progress * 0.8)))`（满引信 2 秒一次 → 归零前 0.4 秒一次）；
- 拆除成功：`qis4c4:ctw`（1.5）；爆炸：`qis4c4:tw`（10.0 / 0.8）；
- 唯一保留的改动：仍是**逐玩家广播**，所以警匪双方都能听见同一份原版音效。

### 👥 队伍身份（CS2 分工）

- `allowed_install_teams`（匪）：名单有内容时只有名单内的队伍能安装；
- `allowed_defuse_teams`（警）：名单有内容时只有名单内的队伍能拆除；
- **`allowed_defuse_teams` 留空时，安装队（匪）依然不能拆包** —— 这是 1.7.3 修掉的漏洞；
- 两份名单都留空 = 原版行为（任何人都能装、能拆）。

### 🧭 排错

- 启动 / 配置重载时打印真正生效的两份名单；
- `/c4roles`：打印两份名单、你自己的队伍、以及你能否安装 / 拆除。

### 🧪 自检

- 专用服务器实测：**143 项检查全部 PASS**（新增队伍身份 12 项、音效身份 5 项）；

### 🏷 掉落的 C4 找不到（新功能）

现象：C4 被击杀掉落 / 掉出背包 / 按 Q 扔出后，原版只剩一个小贴图，草丛里基本找不到。

功能：

- 暗色小牌 + 红框 + `C4` 字样的悬浮标志，悬在掉落物上方，下面一道细光柱指出落点；
- 被方块遮挡时不变暗到不可见（62% 不透明度），隔着墙也能看到“那边有 C4”；
- 随距离缩放（0.55–2.30 倍）并在 72% 处开始淡出，默认 64 格内可见；
- 标志下方一行 `C4 24m` 距离标签（`Font.DisplayMode.SEE_THROUGH`，隔墙可读）；
- 出屏时屏幕边缘出现红色小菱形 + 距离箭头；
- 盯的是“掉落的 C4 物品实体”：捡起即消失、再掉再出现，无需任何同步包。

实现要点：

- 只有 `ItemEntity` 且物品是 C4 才标记 —— 不给已安装的炸弹开透视，防止破坏平衡；
- 世界空间渲染挂在 `RenderLevelStageEvent.Stage.AFTER_PARTICLES`，
  用自建 `RenderType`（`POSITION_COLOR_TEX` + `DepthTestStateShard("always")` + 不写深度 + 加性混合光柱）；
- 遮挡射线检测做了 250ms/实体的缓存，避免每帧对每个掉落物做 raycast；
- 投影/缩放/淡出等数学放在 `util/MarkerMath`，服务端自检可直接验证；
- 新配置 `dropped_c4_marker`（默认 true）、`dropped_c4_marker_range`（默认 64，16–512）。

自检：专用服务器 **121 项全部 PASS**，`verify_jar.py` **66 项全部 PASS**，
另含真实掉落链路（无权限队伍拿 C4 → 自动掉落 → 被定位器发现）与离线成像预览。

## C4-Pro v1.7.1 更新日志（2026-10）

> 重点：`/c4clear`、数据包 `/kill` 真正能清干净所有 C4（包括躲进未加载区块的），
> 且清场不加载区块、不轮询，代价与地图大小无关；提示 UI 改回复用模组原有的独立 UI。

---

### 🧹 “清不掉的 C4”（修复）

现象：`/kill @e[type=qis4c4:c4]` 或 `/c4clear` 之后，C4 有时还在，甚至在继续倒计时。

根因：

1. `/kill` 调用 `Entity.kill()`，而 C4 为了防误伤重写了 `hurt()`（永远返回 false）
   并把 `isInvulnerable()` 设为 true —— `/kill` 对它是空操作。
2. `/c4clear` 只遍历“已加载的实体”和静态 tracker。未加载区块里的 C4 不在场上，
   清场时扫不到；玩家一走近、区块被加载，它又会从存档里复活继续倒计时。
3. 试图靠“加载区块再扫”来兜底：实测区块到达 FULL（level 33）并不会实例化实体，
   必须 entity ticking 才会 —— 于是要么每 tick 轮询（耗性能），要么强行加载区块（卡服+写脏地图）。
   另外每 tick 轮询会顺手把 `(0,0,0)` 这种幽灵坐标写进存档（`/summon` 时 NBT 早于摆位）。

修复：

- **坐标索引**：C4 第一次 tick 时把坐标写进维度存档 `C4SavedData`（`world/data/qis4c4_c4.dat`）。
- **死亡名单（tombstone）**：`/c4clear` 对“只有坐标、实体不在场上”的 C4 只写一条记录，
  不加载区块、不注册 tick 任务；那个 C4 哪天被加载出来，实体在进世界/第一次 tick 时
  查一次名单（O(1) 哈希），命中当场自删，一 tick 都不跑。
- `C4Entity.kill()` 重写为真正的清除（同步清 tracker、存档坐标、记分板、发出提示）。
- `/c4clear` 同时重置 `#C4 c4_condition` 与坐标计分板；玩家在清过的位置重新安装不会误杀。
- 删除所有“挂起坐标 + 每 tick 重试”的临时逻辑，`C4Manager` 恢复为只做引信兜底推进。

实测（真实专用服务器）：C4 放 600,100,600（区块未加载）→ 重启 → `/c4clear`
→ `已清除 1 个C4！（它们藏在未加载的区块里，区块一加载就会立刻销毁，不会再倒计时）`
→ `forceload` 加载该区块 → `[C4] removed by an earlier /c4clear at 600, 100, 600`，
`execute if entity` = 无实体，记分板保持 `0`。

### 🖥️ 提示 UI：改回复用原模组的独立 UI

1.7.0 另写的 HUD 被删除，改回模组自带、已适配好的 `ClientMessageRenderer`：

- 提示与进度都在**准心下方**一行，不挡准心、不挡视野、无背景框；
- 安装进度、拆除进度（`XXX 拆除中 63%` + 细进度条）、全员提示共用这套渲染；
- 拆除面板优先级高于普通提示，600ms 无更新自动消失。

### 其它

- 自检扩到 90 项（新增 `/kill`、`/c4clear`、死亡名单、存档重载、幽灵坐标回归用例）。
- 协议版本仍为 `v2`，客户端与服务端需同为 1.7.1。

## C4-Pro v1.7.0 更新日志（2026-10）

> 重点：修掉“下包后警匪一方听不到滴滴声”，并补齐安装 / 拆除的全员提示与拆除手感。

---

### 🔊 滴滴声：警匪双方、任何位置都能听见（修复）

旧版是三个问题叠加：

1. `level.playSound(..., volume=3.0)` 一次性播放 → 声音包只发给 C4 周围约 48 格内的玩家；
   地图另一边的队伍收不到，中途进入的玩家也永远听不到。
2. 实体卸载/移除时执行 `stopsound @a * qis4c4:c4countdown` → 把所有人的倒计时音效一起掐断，
   而 `COUNTDOWN_SOUND_PLAYED` 又保证它不会重播。
3. C4 所在区块在没有玩家时会被卸载，实体停止 tick → 引信和滴滴声一起“停摆”。

修复：

- 新增 `C4Sounds`：每次声音都由服务端**逐个玩家**发送 `ClientboundSoundPacket`，
  坐标取玩家自身位置，客户端不会因为距离过远把音量衰减成 0（远处保留 0.65 音量下限）。
- 新增单次滴滴声音效 `qis4c4:c4beep`（从原 `c4countdown.ogg` 截取），
  按引信进度由服务端加速播放（约 1 秒一次 → 0.2 秒一次），**任何时刻进服都能对上节奏**。
- 删除全部 `stopsound` 逻辑。
- 安装时给所在区块加 **FORCED 区块票据**，无人值守也会保持加载；拆除/爆炸后释放票据。
- 新增 `C4Manager` 兜底 tick 推进器：实测「区块已加载但 `inEntityTickingRange` 仍为 false」时，
  引信依旧每游戏刻准确推进（专用服务器实测 4 秒消耗 80 tick），不再依赖区块 ticking。

### 🖥️ 安装后全员提示（新增）

- 安装完成瞬间，同维度所有玩家屏幕上方显示小字：**“C4 已被安装”**（4 秒，带半透明底衬）。
- 拆除 / 爆炸同样有全员小字：“C4 已被 XXX 拆除！”“C4 已爆炸！”。

### 📊 拆除提示 UI 改为全员可见（修复）

- 拆除进度改为实体同步字段（`DEFUSE_TICKS` / `DEFUSE_TOTAL` / `DEFUSER`），
  客户端读取后渲染 **“XXX 正在拆除 C4” + 绿色进度条 + 百分比**，不再只有拆除者自己能看到。
- 拆除开始 / 中断也会向全维度广播。

### 🤝 拆除时允许小幅度被推动（改进）

- 旧逻辑用 `player.blockPosition()` 比较，方块坐标一变就中断（被队友轻轻一撞就可能失败）。
- 新逻辑记录拆除起点，按 **水平 1.0 格 / 竖直 1.5 格** 容差判定：
  被实体碰撞、走台阶、被顶起都不会中断；真正走开或超出 4.75 格才中断。
- 拆除计时从 `System.currentTimeMillis()` 改为**服务端 tick**，卡顿/暂停不会造成进度跳变。

### 🐛 其它修复

- 队伍权限判定的 500ms 缓存会跨玩家串号（A 的队伍被当成 B 的），已移除。
- C4 实体不再可被推动 / 不参与碰撞，避免炸弹被顶走。
- 安装进度条会在完成/取消时立即关闭，不再残留。
- 同一位置重复安装会被拒绝（“附近已经有C4了”）。
- 协议版本提升到 `v2`（客户端与服务端需同时更新）。

### 🧪 测试

- 新增服务端自检：`-Dqis4c4.selftest=true`。
  在真实专用服务器（Forge 1.20.1-47.4.16 + 正式发布 jar）上跑：
  安装 → 记分板 → 区块票据 → 滴滴声节奏 → 爆炸 → 剪刀拆除 → 推动容差 → 双人抢拆 →
  NBT 存读档 → `/summon` → 真实 tick 推进，**66 项全部 PASS**，报告写入 `c4-selftest-report.txt`。
- 额外做了 40 秒真实时间实测：`/summon` 后状态立即为 1，20 秒仍为 1，40 秒整爆炸并变为 2。
